# ADR-003: Argon2id KDF Parameters, Package Selection, and Bound Validation Policy

* **Status:** Accepted
* **Date:** 2026-10-10
* **Milestone:** M1 (Secure Vault Core — M1.1)
* **Decision Makers:** Architecture & Security Team
* **Related Documents:** `THREAT_MODEL.md`, `VAULT_FORMAT.md`, `ADR-002`, `SECURITY_TEST_MATRIX.md`

---

## 1. Context

The primary cryptographic defense of the password manager against stolen databases or backup files is maximizing the computational and memory cost of offline dictionary and brute-force attacks against the master password.

Requirements:
1. **GPU/ASIC Resistance (Memory Hardness):** Traditional algorithms (PBKDF2-HMAC-SHA256) require no memory, allowing modern GPUs or specialized hardware (ASICs/FPGAs) to guess billions of passwords per second. A memory-hard KDF is mandatory.
2. **Side-Channel Resistance:** Must protect against cache-timing and execution-timing attacks.
3. **User Experience vs. Security Balance:** Vault unlock must complete within 200 ms – 500 ms on a modern Windows 11 computer to preserve user responsiveness while maximizing attacker expense.
4. **Ecosystem & Maintenance:** Must run securely on .NET 10 with clean cross-platform distribution without brittle native C/C++ compilation.
5. **Denial-of-Service (DoS) Defense:** KDF parameters read from file headers or imports are untrusted. Malicious inputs requesting 64 GB of RAM or 1,000,000 iterations must not exhaust memory or CPU.

---

## 2. Decision

### 2.1. Algorithm Selection: Argon2id (v1.3)
**Argon2id v1.3** (winner of the Password Hashing Competition and standardized in RFC 9106) was selected. Argon2id combines Argon2d's data-dependent memory access (for GPU/ASIC resistance) with Argon2i's data-independent memory access (for side-channel resistance).

### 2.2. Default Parameters (Desktop Profile)
Based on the RFC 9106 low-memory recommendation, the desktop profile is configured as:
* **Memory Cost ($m$):** `64 MiB` ($65,536 \text{ KiB}$).
* **Time Cost / Iterations ($t$):** `3` iterations.
* **Parallelism ($p$):** `4` lanes (optimized for modern 4+ core CPUs).
* **Salt Length:** `32 bytes` (256-bit CSPRNG).
* **Output Key Length:** `32 bytes` (256-bit KEK).

*Expected Performance:* Derivation completes in approximately 150 – 350 ms on modern x64 hardware.

### 2.3. .NET Library Selection: `Konscious.Security.Cryptography.Argon2`
* **Package:** `Konscious.Security.Cryptography.Argon2` (v1.3.1).
* **Rationale:**
  - Pure managed .NET implementation leveraging hardware SIMD vectorization.
  - Eliminates native C/C++ dependencies (`libsodium.dll`), P/Invoke marshalling complexity, and platform packaging hurdles.
  - Verified against RFC 9106 official test vectors.
  - Cross-platform compatible (executes on both Windows and Linux CI without requiring native compilers).
* Pinned centrally in `Directory.Packages.props` and referenced by `PasswordManager.Security`.

### 2.4. Bounded Parameter Validation Policy (Anti-DoS)
Whenever KDF parameters are loaded from untrusted sources (file headers or imports), strict bounding checks are enforced **before allocating memory or initiating computation**:

| Parameter | Minimum Allowed | Default | Maximum Allowed | Violation Action |
| --- | --- | --- | --- | --- |
| **Memory (`MemoryKiB`)** | $16 \text{ MiB}$ ($16,384 \text{ KiB}$) | $64 \text{ MiB}$ ($65,536 \text{ KiB}$) | $512 \text{ MiB}$ ($524,288 \text{ KiB}$) | Immediate fail-closed rejection |
| **Iterations (`Iterations`)** | $1$ | $3$ | $10$ | Immediate fail-closed rejection |
| **Parallelism (`Parallelism`)** | $1$ | $4$ | $16$ | Immediate fail-closed rejection |
| **Salt Length (Bytes)** | $16$ | $32$ | $64$ | Immediate fail-closed rejection |

## 3. Alternatives Considered

1. **Alternative 1: PBKDF2-HMAC-SHA256 (.NET Built-in `Rfc2898DeriveBytes`)**
   * *Pros:* Built-in to .NET, no external dependencies.
   * *Cons:* Zero memory hardness. Even at 600,000 iterations, a modern RTX 4090 GPU evaluates tens of millions of guesses per second. Inadequate against offline database theft.
   * *Outcome:* Rejected.

2. **Alternative 2: Scrypt**
   * *Pros:* Early popular memory-hard function.
   * *Cons:* More vulnerable to side-channel cache-timing attacks than Argon2id. RFC 9106 and the cryptographic community recommend Argon2id as the modern successor.
   * *Outcome:* Argon2id selected.

3. **Alternative 3: Libsodium Native Wrapper (`libsodium-net` / P/Invoke)**
   * *Pros:* Highly optimized C core.
   * *Cons:* Requires distributing platform-specific native binaries across Windows x64, ARM64, and Linux CI environments, introducing packaging fragility and unmanaged memory management risks.
   * *Outcome:* `Konscious.Security.Cryptography.Argon2` chosen for optimal balance of security, performance, and portability.

---

## 4. Security & Architectural Outcomes

* **Brute-Force Cost:** An attacker must allocate at least 64 MiB of high-bandwidth memory for every single password attempt, drastically hindering parallel throughput on GPU clusters.
* **DoS Resilience:** Maliciously configured headers are rejected prior to memory allocation.
* **Master Password Hygiene:** Master password bytes and temporary KEK buffers are immediately zeroed using `CryptographicOperations.ZeroMemory` upon completion of derivation.
