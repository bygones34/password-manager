# ADR-001: Technology Stack, Toolchain, UI Framework, and Deployment Model

* **Status:** Accepted
* **Date:** 2026-10-05
* **Milestone:** M0 (Foundation & Technical Feasibility)
* **Decision Makers:** Architecture & Security Team

---

## 1. Context

We are developing a modern, high-performance, local-first password manager (`PasswordManager`) for Windows 11. The application must:
1. Align with the Windows 11 design language (Fluent Design, Mica, modern controls),
2. Support notification area (System Tray) and flyout window integrations,
3. Enable controlled autofill flows via UI Automation and Win32 APIs,
4. Run on a secure, modern runtime supporting advanced cryptography (.NET `AesGcm`, Argon2id).

Therefore, runtime versions, UI frameworks, target OS versions, and compilation toolchains must be decided and verified in an actual Windows 11 environment.

---

## 2. Decision

Following physical environment tests and build feasibility analysis, the following technical stack and toolchain were selected:

1. **Target Platform & Architecture:**
   - **Operating System:** Windows 11 x64 (Initial target architecture: `win-x64`; ARM64 support planned for later phases).
   - **Minimum OS Version:** Windows 10 Build 17763 (Windows App SDK baseline); primary target Windows 11 22H2 (Build 22621+). The verified test environment is Windows 11 Build 26300.

2. **Runtime & Language:**
   - **.NET 10** (`net10.0-windows10.0.26100.0` TFM).
   - C# 13 / 14 language features, nullable reference types, and strict static analysis (`EnforceCodeStyleInBuild`, Roslyn analyzers).
   - .NET SDK pinned to `10.0.401` via `global.json`.

3. **User Interface (UI):**
   - **WinUI 3 + Windows App SDK (1.6.x)**.
   - `Microsoft.WindowsAppSDK` (v1.6.250205002) and `Microsoft.Windows.SDK.BuildTools` (v10.0.26100.1742).
   - MVVM pattern, XAML data binding, and ResourceDictionaries for design tokens.

4. **Build Toolchain & CLI Compatibility:**
   - Visual Studio Community 2026 Insiders (v18.11.12224.323) and .NET 10 SDK (10.0.401) installed.
   - To ensure Windows App SDK PRI tasks (`Microsoft.Build.Packaging.Pri.Tasks.dll`) execute cleanly under CLI `dotnet build`, an `AppxMSBuildToolsPath` fallback is defined in `Directory.Build.props`. Both Visual Studio IDE and terminal builds operate seamlessly.

5. **Initial Deployment & Packaging Model:**
   - **Unpackaged (`WindowsPackageType=None`)**: Initially, an unpackaged WinUI 3 model is adopted to simplify development, System Tray integration, window handle (HWND) management, and testing.
   - **MSIX Candidate:** At Milestone M9, packaging and distribution requirements (auto-updates, isolated registry, tray startup behavior) will be validated to decide between MSIX or a code-signed alternative installer.

---

## 3. Alternatives Considered

* **Alternative 1: WPF + ModernWPF / Wpf.Ui:**
  * *Pros:* Very mature, broad Win32/tray support, effortless CLI compilation.
  * *Cons:* Older technology compared to native Windows 11 WinUI 3 controls, XBF performance, and Microsoft's official modern Windows client roadmap.
  * *Outcome:* Because the WinUI 3 toolchain and XAML compilation verified cleanly on the physical test system, a WPF fallback was unnecessary.

* **Alternative 2: .NET MAUI (Windows Target):**
  * *Pros:* Cross-platform capabilities.
  * *Cons:* Adds unnecessary abstraction layers on top of desktop-specific Win32/tray/HWND manipulations and autofill flows.
  * *Outcome:* WinUI 3 provides a clean, direct solution for a Windows-focused password manager; MAUI was discarded.

---

## 4. Security & Architectural Implications

* **Performance & Reliability:** WinUI 3 and .NET 10 offer fast startup times and low memory footprints.
* **Isolation:** The UI layer (`PasswordManager.Desktop`) never interacts directly with the database or key manager; all workflows execute via `PasswordManager.Application` ports.
* **Offline Operation:** Dependencies are restricted to local libraries that perform no outbound network calls.

---

## 5. Verification Evidence

On physical Windows 11 (Build 26300), a validation spike was executed:
1. Targeted `net10.0-windows10.0.26100.0` with `Microsoft.WindowsAppSDK` 1.6.250205002 and `Microsoft.Windows.SDK.BuildTools` 10.0.26100.1742.
2. XAML compiler (`XamlCompiler.exe`) successfully compiled `App.xaml` and `MainWindow.xaml` to XBF binaries (`App.xbf`, `MainWindow.xbf`).
3. `makepri.exe` indexed resources and created `WinUITest.pri`.
4. Command line `dotnet build -r win-x64` completed with 0 errors and 0 warnings.
